Linux Server Backup, Restore & Automation

Built and tested a backup workflow for the departmental data on the Linux Mint server — compressed tar archives, content and restore verification with ownership preserved, a bash script wired into cron for nightly runs, logging, 7-day cleanup, and a deliberate failure test to confirm the script fails loudly instead of silently.

tar / gzip Bash Scripting Cron Backup & Recovery
01 // Objective
Configure and test a Linux server backup system for company data. Create compressed backups, verify their contents, restore data to a separate test location, automate backups with cron, implement logging, and test backup failure handling.
02 // Environment
 Linux Mint Server
   │
   ├── /srv/company/        (source — from the Samba file server lab)
   │     ├── IT
   │     ├── HR
   │     └── Finance
   │
   └── /backup/             (destination for compressed archives)
03 // Creating & Verifying a Backup
Step 1 — Create the Backup Directory
sudo mkdir -p /backup
! Dedicated location for storing backup archives
Step 2 — Create a Compressed Backup
sudo tar -czvf /backup/company-backup-$(date +%F).tar.gz /srv/company/
! -c  Creates a new archive
! -z  Compresses using gzip
! -v  Displays files being processed
! -f  Specifies the archive filename
! $(date +%F) inserts the current date

! Example: company-backup-2026-07-23.tar.gz
Step 3 — Verify the Backup Exists
ls -lh /backup/
! Confirms company-backup-2026-07-23.tar.gz was created

! Lesson: a backup file existing is not proof it contains the
! expected data — it still needs to be inspected
Step 4 — Inspect Backup Contents
sudo tar -tzvf /backup/company-backup-2026-07-23.tar.gz
! Lists archive contents without extracting

srv/company/Finance/
srv/company/HR/
srv/company/HR/kevin-test.txt2
srv/company/IT/
srv/company/IT/alex-test.txt

! Ownership and permissions were preserved inside the archive:
!   kevin:hr   alex:it   root:finance
04 // Restore Testing
Restore to a Separate Test Location
sudo mkdir -p /restore-test
sudo tar -xzvf /backup/company-backup-2026-07-23.tar.gz -C /restore-test
! Restoring into a test directory avoids overwriting live
! production data

! Restored structure:
! /restore-test/srv/company/
! ├── Finance
! ├── HR
! └── IT
Verify Restored Ownership & Permissions
ls -l /restore-test/srv/company/
! Finance → root:finance
! HR      → root:hr
! IT      → root:it

! Setgid was also preserved:  drwxrws---
Verify Restored Files
sudo find /restore-test/srv/company/ -type f -ls
! Confirms file paths, owners, groups, and permissions:
!   kevin:hr → HR/kevin-test.txt2
!   alex:it  → IT/alex-test.txt
05 // Bash Backup Script
/usr/local/scripts/company-backup.sh
#!/bin/bash
BACKUP_DIR="/backup"
SOURCE_DIR="/srv/company"
LOG_FILE="/var/log/company-backup.log"
DATE=$(date +%F)

echo "$(date): Backup started" >> "$LOG_FILE"
tar -czf "$BACKUP_DIR/company-backup-$DATE.tar.gz" "$SOURCE_DIR"

if [ $? -eq 0 ]; then
  echo "$(date): Backup successful" >> "$LOG_FILE"
else
  echo "$(date): Backup FAILED" >> "$LOG_FILE"
fi

find "$BACKUP_DIR" -name "company-backup-*.tar.gz" -mtime +7 -delete
echo "$(date): Old backups cleaned up" >> "$LOG_FILE"
Make the Script Executable
sudo chmod +x /usr/local/scripts/company-backup.sh
ls -l /usr/local/scripts/company-backup.sh
! Result: -rwxr-xr-x  — the x flags mean the script can run
06 // Logging & Automatic Cleanup
Backup Log
sudo cat /var/log/company-backup.log
sudo tail -n 5 /var/log/company-backup.log
! The script records:
!   Backup started
!   Backup successful / Backup FAILED
!   Old backups cleaned up
7-Day Retention
find "$BACKUP_DIR" -name "company-backup-*.tar.gz" -mtime +7 -delete
! Automatically deletes backups older than 7 days —
! prevents the backup disk from filling up over time
07 // Scheduling With Cron
Crontab Entry
0 2 * * * /usr/local/scripts/company-backup.sh
! Runs every day at 02:00

sudo crontab -l
! Verifies the scheduled job is installed

02:00 → cron runs script → backup created → log updated
      → old backups cleaned up
08 // Failure Testing
Simulated Failure
Temporarily changed:
  SOURCE_DIR="/srv/company"
to:
  SOURCE_DIR="/srv/does-not-exist"

sudo /usr/local/scripts/company-backup.sh
! Result: Cannot stat: No such file or directory
! Log correctly recorded: Backup FAILED

Source directory was then restored to /srv/company and a
successful backup was run and confirmed in the log.

SSH & Secure Remote Access

Configured SSH version 2 on a Cisco router for encrypted remote management — set up RSA keys, local user authentication, and VTY lines restricted to SSH only. A secure replacement for Telnet.

Cisco Packet Tracer Cisco IOS CLI SSH v2 RSA Encryption Network Security
01 // Objective
Configure SSH version 2 on a Cisco router so that a PC can remotely access and manage the router securely over the network — without needing a physical console cable. SSH encrypts all traffic, unlike Telnet.
02 // Topology
  [ PC 1 ]                   [ PC 2 ]
  192.168.1.10               192.168.1.20
       \                       /
        \                     /
         [ Switch ]
              |
         [ Router R1 ]
         G0/0: 192.168.1.1
         SSH Server
03 // Configuration
Step 1 — Router Interface IP
interface g0/0
ip address 192.168.1.1 255.255.255.0
no shutdown
Step 2 — Hostname & Domain Name (required for RSA)
hostname R1
ip domain-name lab.com
! Router uses hostname + domain name to generate RSA keys
Step 3 — Create Local User
username admin secret password123
! SSH requires username + password for login
Step 4 — Generate RSA Encryption Keys
crypto key generate rsa
! Generates RSA key pair for SSH encryption
! Required before SSH will work
Steps 5–7 — Enable SSH v2 & Configure VTY Lines
ip ssh version 2
! SSH v2 is more secure than v1

line vty 0 4
transport input ssh
! Allows SSH connections only — blocks Telnet
login local
! Uses local username/password database

enable secret cisco123
! Password for privileged EXEC mode

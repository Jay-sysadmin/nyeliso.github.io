Static Routing + ACL Lab

Three-router topology connected over point-to-point /30 links, with static routes providing full LAN-to-LAN reachability and an extended ACL selectively blocking traffic between two of the LANs.

03

Static Routing

A router automatically knows its directly connected networks, but not remote ones — static routes were added on each router so every LAN can reach every other LAN.

R1
ip route 192.168.20.0 255.255.255.0 10.0.12.2
ip route 192.168.30.0 255.255.255.0 10.0.12.2

Meaning: to reach LAN 2 or LAN 3, send traffic to R2.

R2
ip route 192.168.10.0 255.255.255.0 10.0.12.1
ip route 192.168.30.0 255.255.255.0 10.0.23.2
R3
ip route 192.168.10.0 255.255.255.0 10.0.23.1
ip route 192.168.20.0 255.255.255.0 10.0.23.1

Verification: show ip route — static routes appear marked S, e.g. S 192.168.30.0/24 [1/0] via 10.0.12.2

04

Understanding /30 Router Links

/30 networks were used between routers because a point-to-point link only needs two usable addresses. For example, 10.0.12.0/30:

AddressPurpose
10.0.12.0Network
10.0.12.1R1
10.0.12.2R2
10.0.12.3Broadcast

The same logic applies to 10.0.23.0/30 between R2 and R3.

05

Access Control List

Objective: block LAN 1 (192.168.10.0/24) from reaching LAN 3 (192.168.30.0/24) while allowing all other traffic.

ACL on R1
access-list 110 deny ip 192.168.10.0 0.0.0.255 192.168.30.0 0.0.0.255
access-list 110 permit ip any any
Applied to interface
interface gigabitEthernet0/0
 ip access-group 110 in
06

Understanding the ACL

access-list 110 deny ip 192.168.10.0 0.0.0.255 192.168.30.0 0.0.0.255 means: deny IP traffic from 192.168.10.0/24 to 192.168.30.0/24. The wildcard mask 0.0.0.255 represents the entire /24 network.

Why permit ip any any? ACLs have an implicit deny at the end. Logically: deny LAN1 → LAN3, permit everything else, implicit deny everything else. Without the explicit permit line, all other traffic would be blocked too.

07

ACL Direction

The ACL was applied inbound (ip access-group 110 in) on R1 G0/0, because that's the interface LAN 1 traffic enters R1 through.

PC1
↓
SW1
↓
R1 G0/0
↓ ACL applied here
R2
↓
R3
↓
PC5

The ACL is directional — it stops matching traffic as it enters R1, before it ever reaches R2 or R3.

The key concept: the ACL blocks traffic originating from LAN 1, not traffic originating from LAN 3 — reply traffic and traffic in the other direction is unaffected.

09

Verification Commands

  • show ip interface brief — check interfaces
  • show ip route — check the full routing table
  • show ip route static — check static routes only
  • ping <IP-address> — test connectivity
  • traceroute <IP-address> (router) / tracert <IP-address> (PC) — trace the path
  • show access-lists or show access-lists 110 — check ACL entries and match counters
  • show running-config — see where the ACL is applied
10

Syntax to Remember

Static route
ip route DESTINATION MASK NEXT-HOP
Example: ip route 192.168.30.0 255.255.255.0 10.0.12.2
Extended ACL
access-list 110 deny ip SOURCE WILDCARD DESTINATION WILDCARD
Remember: Source → Destination
ACL application
ip access-group 110 in
or: ip access-group 110 out — direction matters

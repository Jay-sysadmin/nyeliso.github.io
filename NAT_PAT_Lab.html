NAT / PAT Lab

A four-PC private LAN behind a router, translated to a single public IP toward an ISP using NAT overload (PAT) — so multiple internal hosts share one public address, each distinguished by port number.

NAT PAT / Overload Default Routing Cisco IOS
01

Topology

PC1 ─┐ PC2 ─┤ PC3 ─┤── SW1 ── R1 ── ISP PC4 ─┘ 192.168.10.0/24 203.0.113.0/30
Connections
PC1 → SW1 Fa0/1  ·  PC2 → SW1 Fa0/2  ·  PC3 → SW1 Fa0/3  ·  PC4 → SW1 Fa0/4
SW1 Gi0/1 → R1 Gi0/0
R1 Gi0/1 → ISP Gi0/0

03

R1 IP Configuration

interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit
interface g0/1
 ip address 203.0.113.2 255.255.255.252
 no shutdown
exit

Note: G0/0 = company LAN, G0/1 = ISP side.

04

ISP Configuration

interface g0/0
 ip address 203.0.113.1 255.255.255.252
 no shutdown
exit

Test: ping 203.0.113.1

05

NAT Inside / Outside

On R1:

interface g0/0
 ip nat inside
exit
interface g0/1
 ip nat outside
exit

Note: Inside = private network. Outside = ISP/public side.

06

PAT (Port Address Translation)

access-list 1 permit 192.168.10.0 0.0.0.255
ip nat inside source list 1 interface g0/1 overload

Note: overload is what makes this PAT — multiple PCs can share the single public address 203.0.113.2, distinguished by port.

07

Default Route

ip route 0.0.0.0 0.0.0.0 203.0.113.1

Note: Sends any traffic to an unknown destination toward the ISP.

08

Verify

  • ping 203.0.113.1 — from a PC, confirms the path out through NAT works
  • show ip nat translations — lists inside/outside interfaces, dynamic translations, hits, misses
  • show ip nat statistics — translation counters

Key result: 192.168.10.x → 203.0.113.2 — that's PAT.

DNS Server Deployment (BIND9)

Deployed and configured a Linux-based DNS server using BIND9 on Linux Mint 22 — built forward and reverse zones for the server.lan domain, added A and PTR records, opened DNS through the firewall, and verified resolution from a Windows 10 client.

BIND9 Linux Mint 22 192.168.1.107/24 DNS
01 // Objective
Deploy and configure a Linux-based DNS server using BIND9. Create forward and reverse DNS zones for server.lan, configure A and PTR records, allow DNS traffic through the firewall, and test resolution from a Windows 10 client.

04 // Installation & Service Check
Step 1 — Install BIND9
sudo apt update
sudo apt install bind9 bind9-utils dnsutils
! bind9      — DNS server software
! bind9-utils — DNS administration utilities
! dnsutils   — testing tools such as nslookup
Step 2 — Check the DNS Service
sudo systemctl status bind9
! Expected: Active: active (running)

sudo systemctl start bind9    Starts the service
sudo systemctl stop bind9     Stops the service
sudo systemctl restart bind9  Restarts the service
sudo systemctl reload bind9   Reloads config without stopping
05 // Forward DNS Zone
named.conf.local — Register the Zone
sudo nano /etc/bind/named.conf.local

zone "server.lan" {
  type master;
  file "/etc/bind/db.server.lan";
};
db.server.lan — Zone Records
sudo cp /etc/bind/db.local /etc/bind/db.server.lan
sudo nano /etc/bind/db.server.lan

$TTL 604800
@   IN  SOA  ns1.server.lan. admin.server.lan. (
              2          ; serial
              604800     ; refresh
              86400      ; retry
              2419200    ; expire
              604800 )   ; negative cache TTL
@   IN  NS   ns1.server.lan.
ns1         IN  A  192.168.1.107
server      IN  A  192.168.1.107
fileserver  IN  A  192.168.1.120
webserver   IN  A  192.168.1.130
06 // Reverse DNS Zone
named.conf.local — Register the Reverse Zone
sudo nano /etc/bind/named.conf.local

zone "1.168.192.in-addr.arpa" {
  type master;
  file "/etc/bind/db.192.168.1";
};

! Network 192.168.1.0/24 → reverse zone octets are written in reverse order
db.192.168.1 — PTR Record
sudo cp /etc/bind/db.127 /etc/bind/db.192.168.1
sudo nano /etc/bind/db.192.168.1

$TTL 604800
@   IN  SOA  ns1.server.lan. admin.server.lan. (
              2  604800  86400  2419200  604800 )
@   IN  NS   ns1.server.lan.
107 IN  PTR  server.server.lan.

! 107 IN PTR server.server.lan. → 192.168.1.107 resolves back to server.server.lan
07 // Validation & Reload
Validate Zones and Config
sudo named-checkzone server.lan /etc/bind/db.server.lan
! Expected: OK

sudo named-checkzone 1.168.192.in-addr.arpa /etc/bind/db.192.168.1
! Expected: OK

sudo named-checkconf
! No output = configuration is valid

sudo systemctl reload bind9
! Loads the new configuration without stopping the service
08 // Firewall
Allow DNS Through UFW (Port 53)
sudo ufw status
sudo ufw allow 53/udp
sudo ufw allow 53/tcp
! UDP handles standard queries
! TCP handles larger responses and zone transfers

11 // Troubleshooting Performed
Problem — DNS Request Timed Out
Initial test from Windows client:
  DNS request timed out.

Investigation:
sudo ss -tuln | grep :53
! Confirmed BIND was listening on 192.168.1.107:53
! Service was healthy — issue was not BIND itself

Root cause: UFW firewall was blocking port 53

sudo ufw allow 53/udp
sudo ufw allow 53/tcp
! After allowing DNS traffic, the Windows client
! successfully resolved server.server.lan → 192.168.1.107

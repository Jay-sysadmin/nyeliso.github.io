Linux File Server & Samba Access Control

Configured a Linux Mint server as a departmental network file server using Samba. Created IT, HR, and Finance shares with group-based access control — Linux users, groups, Setgid permissions, and Samba authentication kept each department's files isolated from the others.

Samba Linux Mint 192.168.1.107/24 Access Control
01 // Objective
Configure a Linux Mint server as a network file server using Samba. Create department-based shared folders and control access using Linux users, groups, file permissions, and Samba authentication — so each department can only reach its own share.

03 // Department Folders & Groups
Step 1 — Create Department Folders
sudo mkdir -p /srv/company/IT /srv/company/HR /srv/company/Finance
! Creates the directories used as network shares
Step 2 — Create Linux Groups
sudo groupadd it
sudo groupadd hr
sudo groupadd finance
! Groups make department permissions easier to manage
!   it       → IT employees
!   hr       → HR employees
!   finance  → Finance employees
Step 3 — Assign Users to Groups
sudo usermod -aG it alex
sudo usermod -aG hr kevin
sudo usermod -aG finance bob
! -aG appends the user to a supplementary group
!   Alex  → it
!   Kevin → hr
!   Bob   → finance
04 // Ownership & Permissions
Group Ownership
sudo chown :it /srv/company/IT
sudo chown :hr /srv/company/HR
sudo chown :finance /srv/company/Finance
! Assigns the department group as group-owner of its folder
! Example: root:it → /srv/company/IT
Permissions — Setgid (2770)
sudo chmod 2770 /srv/company/IT
sudo chmod 2770 /srv/company/HR
sudo chmod 2770 /srv/company/Finance
! 2770 → drwxrws---
!   2 = Setgid  — new files inherit the department group
!   7 = Owner:  rwx
!   7 = Group:  rwx
!   0 = Others: no access

! Setgid means a new file created in /srv/company/IT
! automatically inherits the "it" group, not the creator's
! primary group
Permission Test
sudo -u alex touch /srv/company/IT/test.txt
! Succeeded — Alex is a member of "it"

sudo -u alex touch /srv/company/HR/test.txt
! Denied — Alex is not a member of "hr"
! Confirms Linux group permissions are enforced correctly
05 // Samba Configuration
Back Up Config & Define the IT Share
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.backup
sudo nano /etc/samba/smb.conf

[IT]
  path = /srv/company/IT
  read only = no
  valid users = @it
  force group = it
  create mask = 0660
  directory mask = 2770

! The same block structure was repeated for [HR] and [Finance],
! swapping the path, valid users, and force group each time
SettingPurpose
pathLinux folder being shared
read only = noAllows creating and modifying files
valid users = @itOnly members of the "it" Linux group can access (@ = group)
force groupFiles created via Samba use the correct department group
create mask = 0660New files → rw-rw----
directory mask = 2770New folders inherit Setgid + group permissions
06 // Samba Users & Validation
Validate Configuration
testparm
! Expected: Loaded services file OK.
Add & Enable Samba Users
sudo smbpasswd -a alex
sudo smbpasswd -a kevin
sudo smbpasswd -a bob

sudo smbpasswd -e alex
sudo smbpasswd -e kevin
sudo smbpasswd -e bob
! Linux and Samba use separate authentication databases —
! a user can exist on Linux but still needs to be added to
! Samba separately before authenticating to an SMB share
07 // Firewall & Service
Allow Samba Through UFW
sudo ufw allow samba
! Opens the required SMB network traffic through the firewall
Restart & Verify smbd
sudo systemctl restart smbd
sudo systemctl status smbd
! Expected:
!   Active: active (running)
!   smbd: ready to serve connections

09 // Troubleshooting Performed
Monitoring Active Connections
sudo smbstatus
! Shows connected Samba users, connected shares, client IPs,
! SMB protocol versions, and locked files

! Example:
!   Username: bob
!   Service:  Finance

sudo smbcontrol smbd close-share Finance
! Closes a specific active share session
Windows — Multiple Connections, Same Server
Issue: Windows does not allow connecting to the same server
with more than one username at a time — this happens when
Windows caches an SMB session or saved credentials.

Fix (on the Windows client):
net use * /delete /y
! Clears cached SMB connections. Saved credentials were also
! removed from Windows Credential Manager when necessary.
